## Toolchain (project-scoped)

The build chain is pinned under `.toolchain/` (gitignored, ~5 GB) so the host doesn't need a global Flutter / Android SDK install:

- `.toolchain/flutter/bin/flutter` — Flutter 3.41.7 (anything ≥3.38.4 satisfies `pubspec.lock`)
- `.toolchain/android-sdk/` — Android SDK with `platforms;android-36`, `build-tools;36.0.0`, `ndk;27.0.12077973`, `cmake;3.22.1`, `platform-tools`
- JDK 17 or 21 from the host (`/usr/lib/jvm/java-21-openjdk-amd64` is what `flutter config --jdk-dir` points at)

`yuuna/android/local.properties` hard-codes `flutter.sdk` and `sdk.dir` to those project-scoped paths. Set `PATH`, `ANDROID_HOME`, and `ANDROID_SDK_ROOT` before running anything Flutter:

```bash
export PATH="$PWD/.toolchain/flutter/bin:$PATH"
export ANDROID_HOME=$PWD/.toolchain/android-sdk
export ANDROID_SDK_ROOT=$PWD/.toolchain/android-sdk
```

If `.toolchain/` is missing, see PR #494's `Dockerfile` (root) for the canonical install recipe; bump versions to match `pubspec.lock`.

## Common commands (run from `yuuna/`)

```bash
flutter pub get                                                  # resolve deps; ~10 s
flutter build apk --release --split-per-abi                      # 3 APKs in build/app/outputs/apk/release/; ~6 min
flutter build apk --release --target-platform android-arm64      # single-arch, faster
flutter build apk --debug --target-platform android-arm64        # ~2 min — skips R8/AOT, readable stacktraces
flutter pub run build_runner build --delete-conflicting-outputs  # regenerate *.g.dart (Isar collections + dart_mappable)
adb install -r build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
adb logcat -c && adb shell am start -n app.arianneorpilla.yuuna/.MainActivity && adb logcat -d | grep -E "AndroidRuntime|FATAL"
```

There is **no test suite** in the repo. There is **no lint command in CI** (`flutter analyze` works but produces many pre-existing warnings).

The release build is signed with the **debug** keystore (`signingConfig signingConfigs.debug` in `android/app/build.gradle`), so installs will refuse to upgrade the Play Store version of jidoujisho — uninstall first, or change `applicationId` to install side-by-side.

The debug keystore is pinned to `yuuna/android/keys/debug.keystore` (gitignored — generated locally with `keytool -genkey -keystore yuuna/android/keys/debug.keystore -storepass android -keypass android -alias androiddebugkey -keyalg RSA -keysize 2048 -validity 10950 -dname "CN=Android Debug, O=Android, C=US"`). This avoids the default `~/.android/debug.keystore` which various tooling silently regenerates, breaking `adb install -r` with `INSTALL_FAILED_UPDATE_INCOMPATIBLE` between rebuilds. After cloning fresh, regenerate the keystore once with the command above before the first build.

## yuuna/ architecture

### Barrel imports

Everything in `yuuna/lib/src/<domain>/` is re-exported by a sibling barrel file at `yuuna/lib/<domain>.dart`. Code imports `package:yuuna/dictionary.dart` rather than individual files. When adding a new public symbol, also export it from the barrel.

### State + storage

- **Riverpod** for app-wide DI. Single root `appProvider = ChangeNotifierProvider<AppModel>(...)` in `lib/src/models/app_model.dart` is the god-object holding active language, active dictionary set, decks, current media, etc.
- **Hive** for key/value preferences (settings, history, ephemeral state). Boxes are opened in `AppModel.initialise()`.
- **Isar 3** for the dictionary corpus (entries, headings, tags, frequencies, pitches). Schema files end in `.g.dart` and are generated by `build_runner`.

Generated `*.g.dart` files are committed. Re-run `build_runner` after editing any `@collection`, `@CopyWith`, or `@MappableClass` annotated source.

### Extension points (the codebase is built around three abstract bases)

- **`Language`** (`lib/src/language/language.dart`) — locale, fonts, text segmentation, search prep. Implementations: `JapaneseLanguage`, `EnglishLanguage`. Add a language by subclassing and registering in `AppModel.languages`.
- **`MediaSource`** (`lib/src/media/media_source.dart`) — entries that appear under a `MediaType` (Player / Reader / Viewer / Dictionary). Each source declares `implementsSearch`, `implementsHistory`, and how to launch its detail page. Implementations live in `lib/src/media/sources/`.
- **`DictionaryFormat`** (`lib/src/dictionary/dictionary_format.dart`) — file-format adapters that import a dictionary archive into Isar. Implementations: `YomichanFormat`, `MigakuDictionaryFormat`, `AbbyyLingvoFormat` (in `lib/src/dictionary/formats/`). Each format provides top-level `prepareEntries`/`prepareTags`/etc. functions called from a separate isolate.

`YomichanFormat`'s import path also splits Jitendex-style multi-sense entries into one `DictionaryEntry` per sense at write time. The splitter (`_splitDefinitionBySense` in `formats/yomichan_dictionary_format.dart`) walks the structured-content tree for the canonical `<ul data-content="sense-groups">` marker; if present, each `<li data-content="sense-group">` becomes its own entry sharing the same `DictionaryHeading`. While walking, `_extractAndStripTagSpans` lifts every inline `<span data-content="*-info">` (POS, miscellaneous, field, dialect) into the entry's tags — Jitendex's `tag_bank_*.json` doesn't predeclare these codes, so the import synthesizes `DictionaryTag` rows on the fly using the span's text content (chip name) and `title` (tooltip). Single-sense entries and non-Jitendex Yomichan dictionaries pass through unchanged.

### Card creator pipeline

`CreatorModel` (`lib/src/models/creator_model.dart`) holds the in-progress flashcard. Fields are `Field` subclasses in `lib/src/creator/fields/`. Quick Export and Card Creator UIs both call `MeaningField.flattenMeanings()` → `YomichanFormat.getCustomDefinitionText()` (this is the path that PR #498 hardened against malformed `<ul style>` attributes).

## Local plugin overrides — `yuuna/packages/`

This directory holds patched copies of upstream plugins, wired via `dependency_overrides` in `yuuna/pubspec.yaml`. They exist because the project pulls in many old plugins that no longer build under Flutter 3.41 / AGP 8 / NDK 27 / Kotlin 2.1. Categories of patches:

- **Flutter v2 embedding migration** — strip `static registerWith(PluginRegistry.Registrar)` and the `FlutterMain.getLookupKeyForAsset` calls (replaced with `FlutterInjector.instance().flutterLoader()`). Affects `flutter_ffmpeg`, `flutter_inappwebview`, `flutter_vlc_player`, `fluttertoast`, `package_info`, `mecab_dart`.
- **AGP 8 namespace requirement** — set `namespace` in `android/build.gradle` and remove `package=` from `AndroidManifest.xml`. The root `yuuna/android/build.gradle` *also* has a subprojects shim that auto-derives `namespace` from the manifest's `package=` attribute as a safety net for anything we missed.
- **Android 14 broadcast receiver flag** — `nowplaying` calls `context.registerReceiver(receiver, filter)` without `RECEIVER_NOT_EXPORTED`; patched to use `ContextCompat.registerReceiver(...)`.
- **Kotlin 2.1 strict nullability** — `receive_intent` needs `?.`/`.orEmpty()` on `SigningInfo` accessors.
- **C++14 pin** — `mecab_dart`'s native code uses `register` and `std::binary_function` (removed in C++17). Its `android/CMakeLists.txt` sets `CMAKE_CXX_STANDARD 14` and `-Wno-register`.
- **Pre-Dart-3 SDK constraints** — bumped to `<4.0.0`.
- **Old Flutter Material APIs** — `filesystem_picker` (forked from arianneorpilla, never updated for Flutter 3.16+) gets `headline6` → `titleLarge`, `bodyText1` → `bodyLarge`, `TextButton.styleFrom(primary:)` → `foregroundColor:` patched in.

When adding a new package override, follow the established pattern: copy from `~/.pub-cache/...` into `yuuna/packages/<name>/`, patch the file(s), bump the SDK constraint, set `namespace`, then add a `dependency_overrides` entry. Don't edit pub-cache directly — it gets regenerated.

## Android build configuration

- `compileSdkVersion 36`, `targetSdkVersion 34`, `minSdkVersion 24`, `ndkVersion "27.0.12077973"` — set in **both** `app/build.gradle` and (for libraries) the subprojects shim in `android/build.gradle`.
- AGP 8.6.0 + Kotlin 2.1.0 are pinned in `android/settings.gradle`'s `pluginManagement { plugins { ... } }` block (modern Flutter Gradle setup).
- Gradle wrapper is 8.9.
- `android/gradle.properties` enables `org.gradle.caching`, `parallel`, `configureondemand`, plus `android.ndk.suppressMinSdkVersionError=21` (some plugins still declare `minSdkVersion 16/19`).
- The `applicationVariants.all` rename block in `app/build.gradle` produces filenames like `jidoujisho_yuuna_2.9.1-arm64.apk` in `build/app/outputs/apk/release/` and bumps `versionCodeOverride` per ABI (offsets 1/2/3 for armeabi/arm64/x86_64).

## App theming gotcha

The themes in `AppModel.theme` / `AppModel.darkTheme` were built for Material 2. Flutter 3.16+ flipped `useMaterial3` to default `true`, which produces black-on-black / white-on-white text against the explicit black/white scaffolds. Both `ThemeData(...)` constructors must include `useMaterial3: false`.
